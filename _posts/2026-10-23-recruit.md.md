## Overview

Room: Recruit
A recruitment portal with a file-fetching API and a login dashboard. Two flags: logged in as a normal user, then as admin.

## Enumeration

```bash
22/tcp open  ssh     OpenSSH 8.2p1 Ubuntu 4ubuntu0.7 (Ubuntu Linux; protocol 2.0)
53/tcp open  domain  ISC BIND 9.16.1 (Ubuntu Linux)
80/tcp open  http    Apache httpd 2.4.41 ((Ubuntu))
```

Using `gobuster` we find that there is `sitemap.xml`. In this file we find also that there is `/mail`, and we find this email.

We find this email in `/mail`:

```
From: HR Team <hr@recruit.thm>
To: IT Support <it-support@recruit.thm>
Date: Tue, 14 May 2024 09:32:10 +0000
Subject: Recruitment Portal Deployment Confirmation

Hi Team,

Just a quick update to confirm that the new Recruitment Portal
has been deployed successfully and is functioning as expected.

We've completed basic validation:
- Login page is accessible
- Candidate dashboard loads correctly
- API documentation page is live

As discussed during deployment:
- HR login credentials (username: hr) are currently stored in the application
  configuration file (config.php) for ease of access during
  the initial rollout phase.
- Administrator credentials are NOT stored in the application
  files and are securely maintained within the backend database.

Thanks,
HR Operations
Recruitment Team
```

From this email we know that the username is `hr`, but we still need the password, and in the email they mention that the password of `hr` exists in `config.php`.

## Exploitation - Local File Inclusion

Below in the page they mention that there is an API that can get a file from an outside link:

```
/file.php?cv=
```

I create a server:

```bash
python3 -m http.server
```

Then try to provide this and see what will happen:

```
/file.php?cv=http://MY_TUNNEL_IP:8000/test.pdf
```

They tell me what they can access is just inside files, so we try:

```
cv=file:///var/www/html/config.php
```

And *bang*, we got the `hr` password. We log in now as `hr`.

> This endpoint is a classic [Local File Inclusion](https://owasp.org/www-community/attacks/Path_Traversal) (LFI), reached first by testing SSRF-style remote fetch, then pivoted to `file://` once we learned access was restricted to local files.
{: .prompt-tip }

**Flag (user):** `THM{REDACTED}`

## Privilege Escalation - SQL Injection

The email mentions that the admin credentials live in the backend database, and in the dashboard there is an input field, so we test `sqli`:

```
' OR 1==1 --
```

It is vulnerable. We use `sqlmap` and find the admin credentials.

**Flag (admin):** `THM{REDACTED}`

## Lessons Learned

- Never store credentials in a config file reachable through an LFI/SSRF-style endpoint.
- Validate and whitelist the `cv` parameter instead of fetching any URL or path given.
- Use parameterized queries to prevent SQL injection on the login form.
- Separate user-facing and admin-facing authentication to reduce impact when one is compromised.
